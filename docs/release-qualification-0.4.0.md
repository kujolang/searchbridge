# SearchBridge 0.4.0 release qualification

Qualified on 2026-09-02 against SearchBridge implementation commit `3330bff552ab0bfb9860b0b658ef21cc084d73b5` and Kujo runtime commit `67e880a9688dd5770d4a67311d45aa551e6a6fd6`. The local reference host was macOS Darwin 25.3.0, Intel Core i7-9750H, 16 GiB RAM, with `kujo 1.2.3`.

## Verification record

- `bash scripts/validate.sh`: 285 passed, 0 failed; 13 public 0.2.x goldens remained readable; 27 golden envelope and row-schema contracts were represented by generated SDK consumers; 1,000 deterministic security properties and signature-tamper checks passed.
- `npm ci && npm run check` in `sdk/typescript`, `go test ./...` in `sdk/go`, and `cargo test` in `sdk/rust`: passed.
- Built-in and signed external adapters passed the common conformance report. Provider catalog, immutable snapshots, authentication/format/pagination metadata, documentation links, and fixture hashes matched.
- A fresh local clone at the qualified commit passed `scripts/validate.sh` with the pinned runtime and produced a valid two-provider fixture response for `fetch --capability serp.results --provider all` without credentials.
- GitHub Actions passed [validate](https://github.com/kujolang/searchbridge/actions/runs/33669668967), [SDK compatibility](https://github.com/kujolang/searchbridge/actions/runs/33669669304), [security](https://github.com/kujolang/searchbridge/actions/runs/33669669348), [release-candidate](https://github.com/kujolang/searchbridge/actions/runs/33669669004), and [platform smoke](https://github.com/kujolang/searchbridge/actions/runs/33669669298) for the implementation commit.
- Linux x64, macOS ARM64, and Windows x64 each built the pinned runtime, generated the bundle twice with identical hashes, verified the portable checksum sidecar, extracted into a clean temporary directory, and executed an offline fixture. All three downloaded platform artifacts were independently checksum-verified after the workflow completed.
- The downloaded 90-day release-candidate artifact independently passed its aggregate `RC-SHA256SUMS` and nested runtime checksum. It contains TypeScript, Rust, and Go packages, benchmarks, an SPDX SBOM, SLSA-format provenance, and GitHub build attestations.

## Performance and output budgets

Five warm fixture launches measured 0.23, 0.23, 0.24, 0.24, and 0.24 seconds (median 0.24 seconds), below the 350 ms ceiling and without regression from the post-fix baseline. A later sample under unrelated host load measured 0.37 seconds median and was rejected as a noisy run under the documented stable-threshold rule.

The retained Linux release-candidate benchmark recorded 2,209.342 normalized operations/second across 100 iterations with 56,800 output characters. Its 100,000-row expansion evidence recorded 45.950 ms for 100 registry discoveries, 83.296 ms for 300 routing resolutions, 223.766 ms for bounded CSV parsing (446,895 rows/second), and 4.058 ms for atomic JSONL publication. Streaming retained 1,000 rows, remained atomic, and the agent catalog serialized to 1,164 bytes.

Measured static output sizes were 5,469 bytes for providers, 4,266 for capabilities, 1,165 for the agent catalog, 866 for help, and 21,104 for the full schema set. All are within the budgets in `09-performance-token-budgets.md`.

## Security and release controls

The adversarial corpus covers endpoint templating, redirects/private destinations, deep and oversized responses, credential placement/redaction, cache fingerprints, retry amplification, paid-call preflight, external-package tampering, unknown keys/versions, and write rejection. Submission still requires `--act --yes` on every invocation. The signed Plausible reference package validates canonical manifest/file coverage without shipping a private key.

Release SBOM and provenance are generated by `scripts/release_artifacts.kujo` and bind the release version, source commit, schemas, SDKs, adapters, integrations, and fixtures.

Hosted secret scanning, push protection, vulnerability alerts, Dependabot security updates, and CodeQL are enabled. The active main-branch policy requires review, code-owner approval, resolved threads, current required checks, and linear history protections; release tags matching `v*` reject deletion and non-fast-forward updates.

## External blockers and live evidence

No operator supplied live provider credentials or explicit paid-live authorization. Therefore no live rows or paid quota use are claimed; credential-gated live probes remain opt-in. Semrush live execution and public distribution also remain intentionally blocked pending explicit commercial, entitlement, retention, and redistribution review. Live normalization, pagination, error/quota behavior, provider policy approval, consecutive scheduled compatibility runs, and final tag/publication are the only remaining release gates; they require sanctioned provider accounts or external review rather than repository implementation.
