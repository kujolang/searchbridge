# SearchBridge v1.0 no-extra-cost execution plan

> Closed after the owner approved v1.0.0 on 2026-09-04. See the
> [v1.0 qualification record](release-qualification-1.0.0.md) for release
> evidence and the [v1.1 review checklist](v1.1-review-checklist.md) for the
> three intentionally deferred external checks.

This plan narrowed the broader [v1.0 readiness checklist](v1.0-readiness-checklist.md)
to providers the owner already had or could use without buying another provider
subscription. It is retained as historical execution provenance.

The spending rule is strict: do not start a trial, upgrade a plan, enable a
billable service, or make a metered provider call. If a console asks for billing
or the existing account does not expose the required API dataset, stop and mark
that provider fixture-only. Never assume a free trial is a stable v1 dependency.

## Approved v1.0 scope

These are the intended stable live integrations:

| Provider | Stable v1 capability | Cost boundary |
| --- | --- | --- |
| Google Search Console | `search.performance`, `url.inspection` | Use the owner's existing verified properties and API quotas. |
| Google Analytics 4 | `analytics` | Use an existing standard property and its Data API quota. Do not require Analytics 360. |
| PageSpeed Insights | `page.performance` | The API works with or without a key; use a restricted key for scheduled automation if available. |
| Chrome UX Report | `field.performance` | The CrUX API quota is offered without charge. |
| Cloudflare | `edge.analytics` | Use only datasets available on the owner's current Cloudflare plan. Do not upgrade the plan. |
| IndexNow | `index.submission` | Use only an operator-owned site and its IndexNow key. No paid provider account is part of this scope. |

Cloudflare is conditional: the GraphQL Analytics API exposes datasets according
to the current zone/account plan. If `httpRequests1dGroups` is unavailable,
leave Cloudflare fixture-only rather than changing plans.

These integrations remain implemented and fixture-tested, but they are not
stable live v1 integrations unless the owner later supplies existing access
that incurs no new charge:

- Ahrefs
- DataForSEO
- SerpApi
- Bing Webmaster
- Plausible
- Semrush

Do not call their live endpoints during this plan. Keep
`SEARCHBRIDGE_ENABLE_PAID_LIVE` false. Semrush remains disabled pending its
separate commercial and redistribution review.

## Phase 1 — encode the no-cost support boundary

- [x] Add a machine-readable support tier to each provider: `stable-live`,
  `fixture-only`, `external-reference`, or `disabled`.
- [x] Mark GSC, GA4, PageSpeed, and CrUX `stable-live`.
- [x] Mark Cloudflare `stable-live` only after the existing plan passes the live
  query. Until then, mark it `fixture-only` or `candidate-live`.
- [x] Mark IndexNow `stable-live` only after a controlled submission succeeds.
- [x] Mark Ahrefs, DataForSEO, SerpApi, and Bing Webmaster `fixture-only` for
  this release. Mark Plausible `external-reference` and Semrush `disabled`.
- [x] Preserve fixture execution for every provider regardless of live tier.
- [x] Prevent fixture-only, external-reference, and disabled providers from
  being selected by automatic live routing.
- [x] Require an explicit opt-in for direct live execution of any provider that
  is not `stable-live`; do not weaken paid-call preflight.
- [x] Include the support tier and reason in `providers`, `capabilities`,
  `doctor`, `agent-catalog`, generated SDK types, and documentation.
- [x] Add a gate that fails when a stable-live provider lacks a current policy
  record and complete live-operation evidence.

Acceptance:

- Default agent and CI discovery cannot mistake fixture coverage for stable
  live support.
- Every catalog surface reports the same tier.
- Fixture and compatibility tests for excluded providers still pass.

## Phase 2 — set up credentials without storing long-lived Google secrets

No credential belongs in git, chat, logs, fixtures, Strata, SignalBox, or build
artifacts. Use the GitHub `provider-contract-tests` environment and the
operator's secret manager.

### Google Search Console and GA4

- [ ] Confirm which existing GSC property and GA4 property are safe for bounded
  tests. Use read-only access.
- [ ] Create or select a Google Cloud project without enabling a new billable
  product. Enable only the Search Console API, Google Analytics Data API,
  PageSpeed Insights API, and CrUX API needed by this plan.
- [ ] Prefer GitHub OIDC with Google Workload Identity Federation and a
  least-privilege service account. Configure the trust policy for this
  repository and the `provider-contract-tests` environment only.
- [ ] Grant the service-account identity access to the selected GSC and GA4
  properties. Use the smallest roles that can read the tested data.
- [x] Pin `google-github-actions/auth` to a reviewed commit SHA. Request
  `id-token: write` only in the live-contract job.
- [ ] Mint a short-lived access token during the workflow and pass it to
  SearchBridge through `SEARCHBRIDGE_GSC_TOKEN` and
  `SEARCHBRIDGE_GA4_TOKEN` without printing it.
- [x] Keep generated credential files outside release paths and delete them in
  an `always()` cleanup step.
- [ ] If Workload Identity Federation cannot access either product, stop for a
  documented owner decision. Do not fall back to a committed service-account
  file or stored refresh token.

### PageSpeed and CrUX

- [ ] Run one PageSpeed probe without a key. For repeatable scheduled runs, use
  a restricted API key from the same approved project if available.
- [ ] Create or reuse a restricted CrUX API key. Restrict its API scope and
  rotate it through the GitHub environment secret.
- [ ] Confirm the Google Cloud console shows quota use only and does not require
  a paid plan for the bounded probes.

### Cloudflare

- [ ] Create a separate read-only API token restricted to the test account or
  zone and the minimum Analytics permission.
- [ ] Set a finite token lifetime if operationally practical and document
  rotation/revocation.
- [ ] Store only the token in the GitHub environment secret. Store the zone ID
  as a non-secret variable unless repository policy treats it as sensitive.
- [ ] Confirm the existing plan exposes the exact dataset and fields used by
  SearchBridge. If not, reclassify Cloudflare as fixture-only.

### IndexNow

- [ ] Choose an operator-owned test URL that can be resubmitted safely.
- [ ] Generate and host an IndexNow key using the documented same-host key
  location.
- [ ] Store the key in the GitHub environment secret and never upload it with
  evidence.
- [ ] Keep IndexNow out of scheduled runs unless repeated submissions are
  explicitly approved. A manually dispatched release qualification is enough.

Acceptance:

- Scheduled Google reads obtain fresh credentials without manual token copying.
- Every invalid/expired credential fails with a redacted, provider-scoped
  result.
- No new paid account or subscription is required.

## Phase 3 — expand the live harness to every scoped operation

Change the harness from one probe per provider to an explicit operation matrix.
Each evidence line must name the provider, operation, capability, result schema,
row count, pagination, bounded telemetry, cost class, support tier, run ID, and
source commit. It must not contain properties, URLs, rows, headers, tokens, raw
provider bodies, or credential-bearing errors.

- [ ] GSC: test `search-analytics` with enough data to cross at least one page
  boundary under small row/page limits.
- [ ] GSC: test `inspect-url` against a URL in the verified property.
- [ ] GA4: test `run-report` with a short date range, bounded dimensions and
  metrics, and more than one page when the property has enough rows.
- [ ] PageSpeed: test mobile and desktop strategies if both remain advertised.
- [ ] CrUX: test every advertised form factor against an origin or URL with
  available field data. Treat a valid no-data response as empty, not broken.
- [ ] Cloudflare: test the fixed GraphQL operation with the smallest useful date
  window and cursor/page limits supported by the current plan.
- [ ] IndexNow: run one manual controlled submission with `--act --yes` and
  verify the receipt never claims indexing.
- [ ] For each read provider, test success, valid empty data, invalid
  credentials, permission denial where safely reproducible, and bounded quota
  metadata.
- [ ] Prove cancellation, retry, row, byte, page, call, unit, and elapsed-time
  limits still hold on the live path.
- [ ] Never create artificial rate-limit traffic. Retain a naturally observed
  sanitized 429 shape or rely on the existing transport simulation and record
  that limitation.
- [x] Make missing stable-live evidence fail the workflow. Make fixture-only and
  conditional providers explicit skips rather than false successes.
- [x] Retain sanitized evidence for the release review and delete it according
  to the provider-policy record.

Acceptance:

- Every stable-live operation has a successful bounded proof and the required
  negative cases.
- Three consecutive weekly read-only runs pass after the final live-contract
  change.
- The manually dispatched IndexNow proof passes once after the final write-path
  change.

## Required stop conditions

The agent must stop and ask the owner before:

- enabling billing, starting a trial, upgrading a provider plan, or making a
  metered call;
- changing which providers are stable-live;
- sending a real write request other than the approved IndexNow test;
- storing a long-lived Google key or refresh token;
- weakening request budgets, redaction, endpoint restrictions, adapter trust,
  or `--act --yes`;
- publishing packages, creating `v1.0.0`, or making a public release.

## Per-commit rules

- Work from current `main` on a short-lived branch.
- Keep fixtures as the default development path.
- Add focused tests before changing live code.
- Run focused checks and then `bash scripts/validate.sh` before each commit.
- Use small commits, push them, and leave the working tree clean.
- Update a checkbox only when its evidence is committed or linked.
