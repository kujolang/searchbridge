# SearchBridge v1.1 review checklist

This is the authoritative post-v1.0 follow-up list. The owner approved the
v1.0.0 release on 2026-09-04 and intentionally moved the following external
evidence work into the v1.1 review. These items do not change the v1.0 provider
tier declarations.

## Scheduled live history

- [ ] Accumulate three consecutive successful weekly read-only live-contract
  runs for the stable-live matrix.
- [ ] Confirm every run uses short-lived workload identity and sanitized
  artifacts only.
- [ ] Compare the provider-policy ledger and operation matrix with the released
  v1.0 contracts before changing any support tier.

## Cloudflare Analytics

- [ ] Identify an eligible zone and time range that returns a non-empty dataset
  under the owner's existing plan without enabling billing or an upgrade.
- [ ] Run the bounded Cloudflare Analytics read with
  `--allow-unverified-live`; retain only a sanitized qualification receipt.
- [ ] Keep Cloudflare `fixture-only` unless the implementation, live response,
  normalized contract, degradation behavior, and repeatability all pass review.

## IndexNow

- [ ] Obtain separate owner authorization for the exact URL and invocation.
- [ ] Verify the domain key is hosted correctly without committing or printing
  it.
- [ ] Execute exactly one controlled submission with the required
  `--act --yes` flags and bounded URL list.
- [ ] Record only the sanitized submission receipt and never claim the URL was
  indexed.

## v1.1 disposition

- [ ] Re-run fixture, compatibility, SDK, MCP, security, platform, release, and
  live-contract gates against the proposed v1.1 commit.
- [ ] Update the support matrix, qualification record, security assessment,
  changelog, public documentation, and website using only verified evidence.
- [ ] Preserve unavailable or failed provider capabilities as scoped
  degradation; do not weaken redaction, budgets, endpoint restrictions, or the
  submission boundary to obtain a passing result.
